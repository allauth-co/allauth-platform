---
title: Native AllAuth React header components
description: Add portable user and organization menus with native account-management dialogs.
---

AllAuth React SDK 1.3.4 adds opt-in header menus and native account dialogs while
retaining existing full-page defaults. Use the existing cookie-based same-origin
proxy and import `@allauth/react/styles.css`.

```tsx
<UserButton variant="avatar" managementMode="modal" />
<OrganizationSwitcher
  variant="compact"
  managementMode="modal"
  onSelect={async (organization) => enterTenant(organization.id)}
  onCreate={async (organization) => bootstrapTenant(organization.id)}
  onOrganizationChange={async (organization, reason) => {
    if (reason === "update") await refreshTenant(organization.id);
    if (reason === "leave" || reason === "delete") showTenantChooser();
  }}
/>
```

Native selection/creation completes before app callbacks. Change reasons are
`select`, `create`, `update`, `leave` and `delete`. Do not duplicate host navigation
for selection/creation in the change callback. Failed app bootstrap retries
reuse the created native organization. Hosts still enforce their own tenant
access on the server.

`UserProfileModal` accepts `open`, `onClose`, `initialSection` (`profile` or
`security`) and `onUpdated`. `OrganizationProfileModal` accepts `open`, `onClose`,
`organizationId`, `initialSection` (`general`, `members`, `teams` or `roles`), `onUpdated`, `onLeft`
and `onDeleted`. Their embedded counterparts are `UserProfile` (`section`) and
`OrganizationProfile` (`view`). Callbacks may be async.

The SDK reads real session avatars, connected providers, organizations, roles,
members and invitations. It does not manufacture memberships or unsupported
phone/multiple-email features. Native permissions govern every action; final
owner protection and typed organization-deletion confirmation remain in place.
Dialogs trap and restore focus, dismiss with Escape and lock background scrolling.
Header menus support keyboard navigation and stay within the viewport.

Use host `--allauth-*` CSS tokens and `--allauth-modal-accent` to match the app.
The components use React and React DOM and do not import Next.js APIs.

SDK 1.3.4 clamps the menu’s actual positioned box to the document viewport,
including after resizing or delayed session/organization data changes the trigger.
Size observers track the anchor, menu and viewport; measurements are coalesced
per animation frame and cleaned up when the menu closes.

## Organization teams and custom roles

The working 1.4.0 SDK adds `view="teams"` and `view="roles"` to
`OrganizationProfile`, and the same sections to `OrganizationProfileModal`.
Teams provide native create, rename, delete, and membership management. Deletion
and member removal require confirmation. Team rosters follow the native
requirement that the current user belongs to the team; opening the view does
not automatically join it.

Custom roles can be created and their permissions edited. Built-in roles are
read-only. Existing role names remain fixed to preserve member/invitation
references. Roles assigned to members or pending invitations cannot be deleted
from the UI. Server-side authorization still decides every mutation.

Each control uses its own native permission check, so custom roles can invite,
cancel invitations, edit profiles or manage teams without being an owner/admin.
Custom role assignment is available when the caller can read those roles.
Creation of roles can be delegated independently of permission to list roles.
The SDK checks proposed grants before saving; the native server rechecks them.

Switching organization or account clears drafts and invalidates pending
callbacks, including callbacks that finish after switching away and back.
Install the corresponding SDK proxy update so its allowlist includes native
permission and role endpoints.
