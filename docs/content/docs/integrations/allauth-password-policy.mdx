---
title: AllAuth application password rules
description: Configure password length and optional character requirements separately for each application environment.
---

AllAuth defaults to an **8-character minimum** and **128-character maximum** for
new passwords. Uppercase, lowercase, number and symbol requirements are off by
default. These hosted-service settings do not change Better Auth's library defaults.

Select an application and its Development or Production environment in the
AllAuth console. Open **User & authentication → Email & password → Password
rules**, adjust the rules, and save changes. Each environment has an
independent versioned policy.

| Setting | Accepted values |
| --- | --- |
| Minimum length | Whole number from 6 to 128 |
| Maximum length | Whole number from 8 to 128, at least the minimum |
| Require uppercase | Optional A–Z character |
| Require lowercase | Optional a–z character |
| Require number | Optional 0–9 character |
| Require symbol | Optional character other than a Unicode letter, number or whitespace |

Rules apply when a password is created or replaced. Existing passwords continue
to work for sign-in after rules change; replacements must meet the current rules.

The hosted `/api/config` and same-origin SDK `/api/allauth/sdk/config` endpoints
return the effective public `passwordPolicy` object. The matching hosted forms
and React SDK show and validate the rules before submitting a new password. The
server always enforces the policy, including direct API requests. Update existing
SDK installations to the matching archive/source to consume these settings.

```json
{
  "passwordPolicy": {
    "minLength": 8,
    "maxLength": 128,
    "requireUppercase": false,
    "requireLowercase": false,
    "requireNumber": false,
    "requireSymbol": false
  }
}
```

Management API clients should read `/api/admin/configuration?project=<slug>` and
save the complete returned policy with its current version. Preserve
`passwordPolicy` when changing unrelated settings. Older documents that omit the
field resolve to the defaults above; an omitted field in an update also resolves
to defaults. Stale versions return `409` and must be reloaded before retrying.
