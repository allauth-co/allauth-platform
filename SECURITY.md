# Security reporting

For vulnerabilities in AllAuth's hosted platform, console, service or SDK integration, contact [tom@onsavii.com](mailto:tom@onsavii.com) privately. Include the affected version or source revision, component, reproduction steps and potential impact. Use test accounts and redact credentials, session tokens and personal data. Do not open public issues containing unpatched vulnerabilities or test another customer's account.

We will assess reports and coordinate fixes and disclosure. Support and response are best effort; no guaranteed response time or resolution SLA is offered. Source publication, deployment success or a package update alone does not establish that an affected installation is fixed. Self-hosted operators apply published updates and check their deployments.

For a vulnerability reproduced in unmodified Better Auth, use [Better Auth's private vulnerability reporting](https://github.com/better-auth/better-auth/security/advisories/new) and its policy. Describe issues crossing AllAuth and upstream code so remediation can be coordinated.

Current platform source and released SDK are the maintenance focus. Published SDK archives and tags stay immutable; fixes use new versions. Existing authentication contracts remain compatible unless a release explicitly documents a required migration.
